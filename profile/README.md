<p>「一顿快一顿卡」这件事，多半不是线路带宽不够，而是两个号在抢同一个出口。把老号和新号分成两条线上跑，效果要按天跟踪才看得出来。下面按时间轴排一个三十天的分线计划，每个节点都写明该做什么、拿什么判断做到了。</p>
<h2>一、时间轴先排好，别一边跑一边改</h2>
<p>分线跑最常见的失败方式，是今天换一条线、明天换一个环境，最后说不清是哪一步起了作用。所以先把节点钉死：准备期三天、首登当天、第一周观察、第二到第四周稳定、满月复评。节点之间尽量不插改动，实在要改就记一笔时间戳。</p>

<h3>T-3 到 T-1 要交付什么</h3>
<p>这一段的产出物是两个「环境包」：一条线路配一套独立的浏览器配置目录，里面已经对齐好时区、语言、地理位置权限。环境包做好之后打上编号，后面所有日志都带这个编号。</p>
<h3>线路侧的验收</h3>
<p>查 ASN 归属是否为本地 ISP，查 IP 段分配时间，跑一次两小时的粘性会话看出口是否始终不变。三项都过才入库，任何一项不过就退回换线，别抱着「先用着看」的心态带进后面的阶段。</p>
<h3>环境侧的验收</h3>
<p>打开两个环境，分别访问同一个显示地区信息的页面，两边的城市应该各自对应自己的线路。这一步能同时验证出口和环境有没有串，比单看 IP 更全面。</p>
<h3>哪三天是留给换线的</h3>
<p>线路交付当天通常不能直接用。要查归属、跑一次长会话、确认粘性参数，这些都要时间。准备期留三天，是给一次换线机会留的余量，第一天发现问题还补得上。这三天里可以调环境里的时区语言对齐、可以换浏览器版本，但不允许临时换出口线路——出口一换，前面几天的读数就断档了。</p>
<h2>二、T0：两个号的首登顺序</h2>
<p>首登当天最容易出岔子的地方是顺序。先登老号、再登新号，中间隔十几分钟，比两个同时开要稳。原因是同时登录时，本机网络和资源会短暂争抢，页面加载慢，容易误判成线路问题。</p>
<h3>老号先动还是新号先动</h3>
<p>建议老号先。老号有历史会话，先让它把登录态稳住，再开新号，出问题时能立刻判断是新号自身的问题还是共用资源的问题。反过来操作，一旦新号卡住，老号也被牵连，两个都说不清。</p>
<h3>首登要记的三个数</h3>
<p>登录耗时、是否出现二次验证、出口 IP 是否与预期城市一致。三个数写进台账，后面每次登录都记，形成时间序列，异常会自己冒出来。</p>

<h2>三、T+1 到 T+7：找出「一阵快一阵卡」的根源</h2>
<p>共享出口的典型症状是响应时间呈锯齿状：上午顺、下午卡、晚上又顺。分线之后如果锯齿消失，说明问题确实在出口争抢；如果锯齿还在，方向就错了，要去查本机带宽或浏览器配置。</p>
<h3>怎么读这七天的日志</h3>
<p>按小时聚合响应时间，画两条线分别对应两个号。健康的图形是两条线各自平稳，波动幅度接近；不健康的是两条线此起彼伏，像跷跷板。跷跷板形态基本可以确定资源在互相挤占。</p>
<h3>锯齿还在怎么办</h3>
<p>先排本机：看是不是同一个浏览器实例跑了太多标签页，或者后台在同步大文件。再排线路：单号独占时是否也有锯齿。两轮排查完还在，就换一条出口换城市再试，仍不行则是任务本身太重，跟线路无关。</p>
<h2>四、T+8 到 T+30：各自的稳定期</h2>
<p>这一阶段不再做配置改动，只做观察。老号按原有节奏使用，新号从轻量任务起步，第二周开始加到与老号相当的强度。加量的节奏要慢，一天加两成，别一次拉满。</p>

<h3>加量为什么不能急</h3>
<p>新号的历史行为少，突然上高强度容易触发验证。慢加量给平台一个「这个号是正常人」的观察窗口，也让自己的日志有可比性。</p>
<h3>这一阶段别做的事</h3>
<p>别为了省一条线把两个号合回同一出口，别在观察期内换浏览器版本，别中途改时区。任何一项都会让三十天的对比失去意义。</p>
<h2>五、T+30 以后：什么信号才值得动车</h2>
<p>满月之后可以复评一次，但复评不等于必须改。真正值得动的信号有三类：出口开始漂移且工单没解决、响应时间整体上抬三成以上、二次验证频率明显上升。三类信号都没出现，就保持不动。</p>
<h3>换线的正确姿势</h3>
<p>一次只换一条，换完观察三天。两条一起换，出问题又是两个变量。换线时环境包不动，只改出口配置，这样能确认变化是不是线路带来的。</p>
<h3>什么时候该加第三个号</h3>
<p>两个号稳定运行满一个月、日志无缺口、且第三条线已经验收完毕，再考虑加。加号不是加在同一个环境里，而是复制一套新的环境包，按同样的时间轴重走一遍前两周。</p>
<h2>常见问答</h2>
<h3>两个号分线之后还会互相影响吗？</h3>
<p>答：出口层面不会。但如果跑在同一台机器、同一个浏览器实例里，本机资源仍会互相挤占。环境包要独立到配置目录一级，条件允许时用不同系统账号。</p>
<h3>老号一定要迁到新线路上吗？</h3>
<p>答：如果老号当前线路稳定，可以不迁。分线的核心是「不同号不共用出口」，老号独占原来的线同样满足这个条件。</p>
<h3>三十天太久了，能不能缩短？</h3>
<p>答：可以压到十四天，但要保证每天都跑真实任务，且中间不换配置。天数太短看不出锯齿，只能看有没有明显报错。</p>
<h3>锯齿状波动一定是出口问题吗？</h3>
<p>答：不一定。共用出口是常见原因，本机带宽争抢、后台同步、浏览器标签过多也会造成类似形态。按「先本机、后线路」的顺序排。</p>
<h2>合规提示</h2>
<p>分线运行的前提是账号由自己或所在团队合法持有，不得代他人注册或出借账号。</p>
<p>记录日志时请勿留存完整的对话内容与个人身份信息，只保留排障所需的出口、时间与状态字段。</p>
